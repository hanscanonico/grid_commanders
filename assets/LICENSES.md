## Board sprites — generated

Both atlases — every unit, terrain tile and property building the board draws —
are the output of the sibling
[`sprite_generator`](https://github.com/hanscanonico/sprite_generator) repo: a
deterministic Python voxel pipeline in which every sprite is a hand-authored
model, rendered in one dimetric projection with one light, one palette and one
outline rule across the whole roster. There is no third-party art in either
sheet: the PixVoxel CC0 pack the project shipped with, and the hand-vendored
sprites that filled the columns the pack lacked, were both retired when the
generator's atlases replaced them wholesale (2026-08-14). The faction ramps are
read from this game's own `CommanderVisuals.FactionTheme` values, so the
sprites and the UI chrome can never disagree about a faction's colour.

The atlas's **five property columns are transparent overlays** — the building,
its plinth and an opaque dithered shadow, alpha everywhere else — so a city is
an object rather than a green square baked onto whatever it stands on. Which
ground goes under one is `TerrainDB.GROUND_ID`'s single answer.

Rebuild with `make tiles`, which runs the generator from a checkout beside this
repo (`SPRITEGEN=<path>` overrides). The committed sheets — both atlases, the
six autotile families and the sea's phase sheet — are its exact output, so a clone without the
generator still plays and still passes every gate; the per-cell PNGs under
`sprites/units/` and `sprites/iso_buildings/` are the same art exported cell by
cell, kept as reviewable reference copies.

## Typography — the two faces

The menu and commander-select screens are set in two OFL-licensed pixel faces,
vendored under `fonts/` and read through `scenes/common/ui_theme.gd` (`UiTheme`),
the menu's presentation authority (menu-revamp plan D2). Both were the "chosen
substitutes" the design-system handoff named because the repo shipped no UI font;
the substitution ends there — they are the game's faces now. The handoff's
Google-Fonts `@import` cannot ship in an engine build, so the TTFs are vendored
outright: it is the only form that works offline and in an export.

- **Pixelify Sans** — display and UI chrome. Vendored as the single variable TTF
  (`PixelifySans-Variable.ttf`); `UiTheme` asks it for its 700-weight instance for
  the wordmark and titles rather than carrying a second file. It ships standard
  `liga` ligatures whose merged glyphs are unreadable at pixel size, so `UiTheme`
  serves the face with them switched off — its `_LIGA_TAG` comment owns the
  reasoning. Silkscreen carries no such ligatures.
  - **Copyright:** 2021 The Pixelify Sans Project Authors — <https://github.com/eifetx/Pixelify-Sans>
- **Silkscreen** — micro-labels, numerals, badges. The Regular and Bold cuts are
  vendored (`Silkscreen-Regular.ttf`, `Silkscreen-Bold.ttf`).
  - **Copyright:** 2001 The Silkscreen Project Authors — <https://github.com/googlefonts/silkscreen>

Both are licensed under the **SIL Open Font License, Version 1.1**; the full
licence text ships beside each family as `fonts/PixelifySans-OFL.txt` and
`fonts/Silkscreen-OFL.txt`. Antialiasing is switched off in `UiTheme` so the
glyphs rasterise on the same pixel grid the tile and unit art lives on.

## Commander portraits — generated vector art

The portraits under `portraits/` are project-original and generated, not
vendored: `tools/commander_face_svg.gd` draws each general as an SVG — pose,
backdrop, prop, palette — and `tools/generate_portraits.gd` rasterises it. They
are the "Heroic Commander Portraits" design handoff, drawn to its spec rather
than exported from it, so no third-party pixels enter the tree. The only colours
that are not the handoff's own are the faction hues, read from
`CommanderVisuals`. Rebuild with `make portraits`.

## Retired: PixVoxel Revised Wargame Sprites

Until 2026-08-14 the land units and the city/base/hq buildings came from Tommy
Ettinger's CC0 [PixVoxel Revised Wargame
Sprites](https://opengameart.org/content/pixvoxel-revised-isometric-wargame-sprites),
with hand-vendored fills for the columns and faction rows the pack lacked. The
generator's atlases replaced all of it; the vendored pack sources
(`sprites/pixvoxel_src/`) and the compositing pipeline
(`tools/build_pixvoxel_atlases.sh`, `tools/paste_unit_sprites.gd`) left with
it. This note is kept because git history still contains the pack's sprites,
and their CC0 dedication is what made that lawful.
