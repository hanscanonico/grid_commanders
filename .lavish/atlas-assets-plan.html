Goal

Replace the mixed PixVoxel-pack + hand-vendored art with one generator that deterministically produces every unit and terrain sprite in a single, higher-detail style — so adding or retuning art is a code edit, not an asset hunt.

Current state

Generator rewritten and validated: contract sizes match the game's atlases, two independent runs hash identically, and a demo map proves the sheet in context. The game still builds its atlases via make tiles (ImageMagick + pack sprites).

Adoption plan

Decision: how grid_commanders consumes this art. The hazard to design around: the game's make tiles currently rebuilds both atlases from its own pipeline and would silently overwrite anything installed.

A — Commit atlases directly

Run --install, commit the two PNGs in the game repo, delete the ground / sprites / unit-sprites / unit-placeholders steps from make tiles.
  • Smallest diff, art becomes plain committed assets
  • Game repo loses the ability to rebuild its own art
  • Art edits require touching two repos by hand

B — Feed the paste pipeline

Drop the 90 + 25 cell PNGs into assets/sprites/… and let the existing compositor keep assembling atlases.
  • No Makefile changes at all
  • Land units' neutral/red/blue rows still come from the old pack — two art styles on one sheet
  • Keeps the ImageMagick + pack dependency alive
RECOMMENDED

C — Make tiles calls this generator

Replace the atlas steps of make tiles with sprite_generator.py --install (path configurable), keep the game's import step.
  • One source of truth; a rebuild in either repo converges
  • Retires ImageMagick and the PixVoxel compositing entirely
  • Atlases become fully project-original art (licensing simplifies)
  • Game build grows a Python + Pillow dev dependency
8

Risks & open questions

Overwrite hazard until route C lands.

Installing atlases today and later running make tiles in the game repo reverts them to pack art. Mitigation: adopt C (or A with the Make steps deleted) in the same change.

Byte-stability is pinned to Pillow's PNG encoder.

Pixels are deterministic forever; the exact bytes could shift on a Pillow major upgrade. If CI ever asserts atlas hashes, pin pillow in this repo's requirements.

Zoom-1 downsampling.

On screen at 1x the 64px cells sample 4:1 nearest, softening 2px detail. Grounds were authored at ≥4px granularity for this; units carry 2px detail exactly like the shipped pack already did, so nothing regresses — but battle-zoom is where the new detail pays off.

Q1 — Any unit or tile for another design pass?

Every sprite is one small model function now. Annotate the card above (shape, weapon, stance, color balance) and it's a targeted edit.

Q2 — Neutral row styling.

Kept the pack's white/grey so neutral never reads as a team. Alternative: the UI's slate-grey neutral theme. Preference?

Q3 — Baked-in hover shadows for air units.

Air units carry their detached drop shadow inside the cell, like the shipped art. If the game ever animates altitude, shadows should move to a separate layer instead.
